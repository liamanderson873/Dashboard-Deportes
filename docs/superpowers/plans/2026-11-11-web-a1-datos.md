# Web, fase A1 (datos): plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ampliar la base de datos y la ingesta de Python con más ligas, perfiles de equipo, plantillas, goleadores y estadísticas avanzadas de equipo (xG, tiros, córners...), listas para que las lea la web de Next.js.

**Architecture:** Se mantiene el paquete `sports_dashboard`. El esquema se amplía de forma idempotente (`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`, tablas nuevas con `CREATE TABLE IF NOT EXISTS`) para no perder los datos ya cargados. football-data.org aporta equipos, plantillas, goleadores y partidos con un cliente ampliado; football-data.co.uk se importa desde CSV descargados a mano por el usuario.

**Tech Stack:** Python 3.12+, pandas, SQLAlchemy 2 + psycopg 3, PostgreSQL 16 en Docker, requests, pytest, responses.

**Spec:** `docs/superpowers/specs/2026-11-11-dashboard-web-nextjs-design.md`

## Global Constraints

- Directorio del proyecto: `01-dashboard-deportes/`. Todos los comandos y rutas de este plan son relativos a él salvo que se diga lo contrario.
- Solo planes gratuitos. football-data.org: unas 10 peticiones por minuto, y el cliente espera 6,5 s entre peticiones.
- **Sin raspado de webs.** Los CSV de football-data.co.uk los descarga el usuario a mano.
- **Los datos de terceros no se suben a git:** `data/external/` va en `.gitignore`. Sí se versiona `data/team_aliases.csv`, que es trabajo propio.
- Las claves van en `.env` (ignorado por git); `.env.example` queda con valores vacíos.
- PostgreSQL local publicado en `127.0.0.1:5433`; URLs con `127.0.0.1`, no `localhost`.
- Competiciones iniciales, todas `TIER_ONE` en la clave del usuario: `PD`, `PL`, `SA`, `BL1`, `FL1`. Temporadas: 2024, 2025, 2026.
- Hechos verificados: `GET /competitions/{code}/teams?season=` devuelve en una sola petición los 20 equipos con `squad` (`id`, `name`, `position`, `nationality`, `dateOfBirth`), `coach.name`, `crest`, `venue`, `clubColors`, `founded`, `website`, `shortName`, `tla`. `GET /competitions/{code}/scorers?season=&limit=` devuelve por goleador `player`, `team`, `playedMatches`, `goals`, `assists`, `penalties`. Los partidos traen `score.halfTime.{home,away}`.
- El CSV de football-data.co.uk (ej. `SP1.csv` de 2026-27) trae: `Date`, `HomeTeam`, `AwayTeam`, `HTHG`, `HTAG`, `HxG`, `AxG`, `HS`, `AS`, `HST`, `AST`, `HF`, `AF`, `HC`, `AC`, `HY`, `AY`, `HR`, `AR`, `Referee`. Las temporadas antiguas pueden no traer `HxG`/`AxG`.
- Los 41 tests actuales siguen pasando en cada tarea. Los tests que usan la base (`engine`, `seeded`) requieren `docker compose up -d`.

## Review Focus

- Una competición que el plan gratuito no da (HTTP 403) no debe abortar la carga de las demás: se registra y se sigue.
- Equipo sin plantilla, sin entrenador o sin escudo (`squad: []`, `coach: null`): se guarda con valores nulos, sin fallar.
- Goleador cuyo equipo o jugador aún no está en la base: se inserta antes de usarlo, sin error de clave foránea.
- Actualizar la base de la fase 1 con `init_schema` no debe borrar los datos ya cargados.
- CSV con equipos que no se reconocen: se listan **todos** los nombres sin reconocer y no se importa nada. CSV sin columnas de xG, o con líneas vacías al final: no falla. Partido del CSV que no existe en la base: se cuenta aparte, no es un error.
